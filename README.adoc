= bundle-cat

A small tool to find and print files from support bundles.

== Library use

The package is named `bundle-cat` and is imported in Rust as `bundle_cat`.
Its default feature set includes `cli`. Library-only consumers can disable
default features to omit the optional `clap` dependency and binary:

[source,toml]
----
[dependencies]
anyhow = "1.0"
bundle-cat = { git = "https://github.com/oxidecomputer/bundle-cat", default-features = false }
zip = "8.2"
----

Construct a bundle from a ZIP archive:

[source,rust]
----
use bundle_cat::Bundle;
use std::fs::File;
use std::io::BufReader;
use zip::ZipArchive;

let reader = BufReader::new(File::open("support-bundle.zip")?);
let archive = ZipArchive::new(reader)?;
let bundle = Bundle::from_archive(archive)?;
----

Or open an unpacked support bundle directory:

[source,rust]
----
use bundle_cat::Bundle;

let bundle = Bundle::open_dir("unpacked-support-bundle")?;
----

Custom synchronous backends implement the object-safe `BundleSource` trait.
They provide owned relative UTF-8 names, files supporting sequential `Read`,
and optional length and modification-time metadata. For example, a boxed
custom source can be consumed while listing sleds:

[source,rust]
----
use anyhow::Result;
use bundle_cat::{Bundle, BundleSource};

fn list_sleds(source: Box<dyn BundleSource>) -> Result<()> {
    let bundle = Bundle::from_source(source)?;
    bundle.sleds(std::io::stdout())?;
    Ok(())
}
----

The CLI remains ZIP-only; directory and custom sources are library APIs. ZIP
lookup is name-based, so duplicate ZIP entry names are unsupported.

Structured consumers can use `parse_sled_txt` and `parse_ereport_path`, or
stream matching files with `Bundle::for_each_ereport` and
`Bundle::for_each_log`. Ereport callbacks receive owned metadata and raw
contents. Log callbacks receive a complete reader that must be consumed before
the callback returns and must not re-enter the same `Bundle`.

== Usage

List sleds in the bundle:

[source]
----
$ bundle-cat bundle_2025-09-24_10-30.zip sleds
SERIAL     	ID
BRM03250047	0f16e501-0b41-4b14-aa24-a81b791d71fb
BRM03250027	282dd3a4-dbd3-4bc6-9715-350be2328816
...
----

List zones in the bundle, optionally filtering by sled serial or id:

[source]
----
$ bundle-cat bundle_2025-09-24_10-30.zip zones --sled BRM03250047
global
oxz_crucible_2199a890-b984-4f69-aba9-b0193c038772
...
----

List all files with names ending in '.json':

[source]
----
$ bundle-cat bundle_2025-09-24_10-30.zip logs --sled BRM03250047 --path '*.json' --list
rack/34261901-b550-451c-9bd0-3926bb29c40d/sled/0f16e501-0b41-4b14-aa24-a81b791d71fb/dladm.json
rack/34261901-b550-451c-9bd0-3926bb29c40d/sled/0f16e501-0b41-4b14-aa24-a81b791d71fb/health-check.json
...
----

List all log files for the `dendrite` service:

[source]
----
$ bundle-cat bundle_2025-09-24_10-30.zip logs --service dendrite --list
rack/34261901-b550-451c-9bd0-3926bb29c40d/sled/690650fd-4f95-4b3a-b2ec-977d47154383/logs/oxz_switch/dendrite/archive/oxide-dendrite:default.log.1758688200

...
----

Look at all service logs from a specific sled around the time a given instance was created or destroyed:

[source]
----
$ bundle-cat bundle.zip logs --sled '0fadd43a*' \
    --after '2026-04-02T17:50:00Z' --before '2026-04-02T18:00:00Z'
----

Or more specifically, logs for a given service from said sled in the time window:

[source]
----
$ bundle-cat bundle.zip logs --sled '0fadd43a*' --service sled-agent \
    --after '2026-04-02T17:50:00Z' --before '2026-04-02T18:00:00Z'
----

Pipe each matching file through `jq` or https://github.com/oxidecomputer/looker[looker] for pretty-printed, colorized output:

[source]
----
$ bundle-cat bundle_2025-09-24_10-30.zip logs --service sled-agent --exec 'jq -C .'
----

[source]
----
$ bundle-cat bundle_2025-09-24_10-30.zip logs --service sled-agent | looker
----
